# Практическая работа № 1 — эмулятор командной оболочки

**Дисциплина:** Конфигурационное управление  
**Вариант:** № 16  
**Язык реализации:** Python  
**Объём реализации:** этапы 1–3

## 1. Описание проекта

Проект представляет собой консольный эмулятор командной оболочки UNIX-подобной операционной системы. Программа принимает команды пользователя, разбирает их на имя команды и аргументы, выполняет поддерживаемые команды и выводит результат.

Для работы с файлами и каталогами используется виртуальная файловая система (VFS). Она загружается из XML-файла в структуры данных Python и далее обрабатывается в оперативной памяти. Исходный XML-файл при выполнении команд не изменяется.

В этой версии реализованы первые три этапа практической работы: REPL, конфигурация запуска и виртуальная файловая система.

## 3. Реализованные этапы

### Этап 1. REPL

Реализован интерактивный цикл чтения, разбора и выполнения команд.

Возможности:
- консольный интерфейс (CLI);
- приглашение к вводу, содержащее имя VFS и текущий каталог;
- разбор команд и аргументов с помощью модуля `shlex`;
- поддержка аргументов в одинарных и двойных кавычках;
- сообщение об ошибке при неизвестной команде, неверном количестве аргументов или незакрытых кавычках;
- команды `ls`, `cd` и `exit`.

### Этап 2. Конфигурация

Для настройки эмулятора используются параметры командной строки:
- `--vfs` — путь к XML-файлу виртуальной файловой системы;
- `--script` — путь к стартовому скрипту с командами эмулятора.

При запуске программа выводит заданные параметры. Если указан стартовый скрипт, команды выполняются последовательно. Вводимые команды и результаты их выполнения отображаются на экране. Выполнение прекращается при первой ошибке или после команды `exit`.

Если параметр `--vfs` не указан, создаётся пустая виртуальная файловая система с именем `vfs`.

### Этап 3. Виртуальная файловая система (VFS)

Источником данных VFS является XML-файл. При загрузке программа строит дерево каталогов и файлов в памяти.

Поддерживаются:
- корневой элемент XML `vfs`;
- элементы `dir` для каталогов;
- элементы `file` для файлов;
- вложенные каталоги;
- текстовое содержимое файлов;
- абсолютные и относительные пути;
- переход к родительскому каталогу через `..`;
- проверка структуры XML, имён элементов и атрибута `name`;
- обнаружение повторяющихся имён в одном каталоге;
- обработка отсутствующего файла и некорректного XML.

Операции чтения и перехода выполняются над объектами VFS в оперативной памяти. Физические файлы и каталоги операционной системы командами эмулятора не изменяются.

Пример структуры XML:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs>
    <dir name="home">
        <file name="welcome.txt">Добро пожаловать!</file>
        <dir name="documents">
            <file name="notes.txt">Текст заметок.</file>
        </dir>
    </dir>
    <file name="root_file.txt">Файл в корне.</file>
</vfs>
```

В каталоге `demo` находятся два примера VFS:
- `vfs_min.xml` — минимальная файловая система с одним файлом;
- `vfs.xml` — файловая система с несколькими каталогами и вложенностью более трёх уровней.

## 4. Команды эмулятора

| Команда | Назначение | Пример |
|---|---|---|
| `ls [путь]` | Показывает содержимое каталога или имя файла VFS. Путь необязателен; без него используется текущий каталог. | `ls`, `ls home` |
| `cd [путь]` | Меняет текущий каталог VFS. Без аргумента выполняет переход в корень. | `cd home`, `cd ..`, `cd /` |
| `exit [код]` | Завершает работу эмулятора. Код выхода необязателен и должен находиться в диапазоне от 0 до 255. | `exit`, `exit 1` |

Аргументы, содержащие пробелы, можно заключать в одинарные или двойные кавычки. Например:

```text
ls "my documents"
ls 'my documents'
```

Команды работают только с виртуальной файловой системой.

## 5. Требования

- Python версии 3.9 или выше;
- Bash для запуска файлов `.sh`;
- дополнительные сторонние Python-библиотеки не требуются.

## 6. Запуск программы

Перейдите в каталог `config-shell-emu`.

При необходимости сделайте скрипты исполняемыми:

```bash
chmod +x run.sh run_tests.sh scripts/*.sh
```

### Интерактивный запуск с полной VFS

```bash
./run.sh --vfs demo/vfs.xml
```

### Запуск с минимальной VFS

```bash
./run.sh --vfs demo/vfs_min.xml
```

### Запуск без параметра VFS

```bash
./run.sh
```

В этом случае будет создана пустая VFS с именем `vfs`.

### Запуск стартового скрипта

```bash
./run.sh --vfs demo/vfs.xml --script demo/stage2_script.txt
```

Демонстрационный скрипт в конце содержит неизвестную команду `foo bar`. Она предназначена для проверки обработки ошибки и остановки дальнейшего выполнения. Поэтому ненулевой код завершения в этом примере ожидаем.

## 7. Тестирование

Для запуска автоматических тестов выполните:

```bash
./run_tests.sh
```

Либо, если у скрипта нет права на исполнение:

```bash
bash run_tests.sh
```

Тесты разделены по этапам:

- **Этап 1:** разбор обычных команд, аргументов в кавычках, незакрытых кавычек и обработка неизвестной команды.
- **Этап 2:** остановка стартового скрипта после первой ошибки, завершение после `exit` и обработка отсутствующего файла скрипта.
- **Этап 3:** работа `ls` и `cd`, переходы по каталогам, обработка неверных путей, а также проверка корректности XML и ошибок его структуры.

## 8. Демонстрационные скрипты

Скрипты расположены в каталоге `scripts`:

| Файл | Назначение |
|---|---|
| `test.vfs.sh` | Запускает эмулятор с минимальной VFS. |
| `test_all.sh` | Запускает эмулятор с полной VFS и демонстрационным стартовым скриптом. |
| `test_script.sh` | Запускает стартовый скрипт без явного указания VFS; демонстрирует обработку ошибки при обращении к отсутствующему каталогу. |

Их можно запускать через Bash:

```bash
bash scripts/test.vfs.sh
bash scripts/test_all.sh
bash scripts/test_script.sh
```
