# Вариант 16 — граф зависимостей Maven

Практическая работа №2 по дисциплине «Конфигурационное управление».
Проект написан на Python 3.10+ и использует только стандартную библиотеку
для основной работы. `pytest` нужен только для запуска тестов.

## 1. Что делает программа

Программа получает прямые зависимости Java-пакета из Maven POM, строит
транзитивный граф, находит циклы, рассчитывает порядок загрузки и выводит
схему PlantUML. По настройке она также печатает ASCII-дерево.

Для проверки без интернета есть тестовый режим. В нём граф читается из
обычного текстового файла, а имена пакетов задаются заглавными латинскими
буквами.

## 2. XML-настройки

Путь к XML передаётся первым аргументом. В конфигурации ровно шесть
параметров:

| Параметр | Для чего нужен |
|---|---|
| `package_name` | Maven: `groupId:artifactId`; тест: `A`, `B` и т. п. |
| `repository` | URL Maven-репозитория или путь к тестовому файлу |
| `test_mode` | `true` — тестовый граф, `false` — Maven |
| `version` | Версия Maven-пакета; в тестовом режиме оставляется `1.0` |
| `ascii_tree` | `true` — вывести ASCII-дерево |
| `max_depth` | Максимальная глубина; `0` оставляет только корень |

Путь к тестовому файлу считается относительно папки XML. Пример готовых
настроек находится в `examples/`.

## 3. Этапы задания

- **Этап 1:** чтение XML, проверка шести параметров и вывод `ключ=значение`.
- **Этап 2:** загрузка POM обычным HTTP-запросом и разбор прямых зависимостей.
- **Этап 3:** построение транзитивного графа итеративным DFS без рекурсии,
  ограничение глубины и поиск циклов.
- **Этап 4:** вывод порядка загрузки. Если найден цикл, программа сообщает,
  что корректного порядка загрузки нет. Для сравнения с установленным Maven
  предусмотрен отдельный флаг `--compare-maven`.
- **Этап 5:** вывод PlantUML и, если включено в XML, ASCII-дерева.

Для демонстрации трёх разных графов есть настройки `config_demo_alpha.xml`,
`config_demo_beta.xml` и `config_demo_gamma.xml`.

## 4. Запуск на macOS и Linux

Откройте Терминал в папке проекта.

```bash
# Проверить тесты
python3 -m pip install -r requirements.txt
python3 -m pytest tests -v

# Этап 1 — параметры XML
./run.sh examples/config_test_simple.xml --stage 1

# Этап 2 — прямые зависимости
./run.sh examples/config_test_simple.xml --stage 2

# Этап 3 — граф и цикл
./run.sh examples/config_test_cycle.xml --stage 3

# Этап 3 — ограничение глубины
./run.sh examples/config_test_depth.xml --stage 3

# Этап 4 — порядок загрузки
./run.sh examples/config_test_simple.xml --stage 4

# Этап 4 — программа откажется от порядка при наличии цикла
./run.sh examples/config_test_cycle.xml --stage 4

# Этап 5 — PlantUML и ASCII
./run.sh examples/config_test_simple.xml --stage 5
```

Для Windows можно использовать `run.bat` или команду:

```text
python src\main.py examples\config_test_simple.xml --stage 5
```

Для демонстрации ошибок каждого XML-параметра можно выполнить:

```bash
for file in examples/errors/*.xml; do
  ./run.sh "$file" --stage 1
done
```

## 5. Демонстрация трёх пакетов

Запустите три команды. Каждая выводит отдельную диаграмму PlantUML:

```bash
./run.sh examples/config_demo_alpha.xml --stage 5
./run.sh examples/config_demo_beta.xml --stage 5
./run.sh examples/config_demo_gamma.xml --stage 5
```

Ожидаемые текстовые диаграммы также сохранены в `examples/results/`.
Их можно открыть в любом просмотрщике PlantUML.

## 6. Сравнение с Maven

Основная программа сама скачивает и разбирает POM. Она не запускает Maven
для получения зависимостей. Для отдельного сравнения на этапе 4 можно
установить Apache Maven и выполнить:

```bash
./run.sh examples/config.xml --stage 4 --compare-maven
```

Флаг запускает `mvn dependency:tree` во временном проекте и сравнивает
списки координат. Для этой команды нужны установленный Maven и доступ
к репозиторию. Без Maven обычная работа программы не зависит от него.

## 7. Тестирование

```bash
./run_tests.sh
```

Тесты проверяют XML, ошибки параметров, чтение тестового графа, Maven POM,
итеративный DFS, короткие и длинные пути, глубину, циклы, порядок загрузки,
PlantUML, ASCII и работу CLI. Сетевые запросы не нужны для запуска тестов.

## 9. Ограничения разбора Maven

Разбор POM сделан вручную, без Maven Resolver и библиотек менеджера
пакетов. Поддерживаются XML namespace, прямые зависимости, цепочка родительских
POM (до 10 уровней), наследование простых свойств и `dependencyManagement`,
а также отбор по scope и `optional`.

Это учебная реализация, а не полный Maven Model Builder. Она не разрешает
импортированные BOM, все виды профилей, exclusions, конфликты версий и
классификаторы. Если версию зависимости нельзя определить из POM и его
родителей, такая запись пропускается. Эти особенности могут дать расхождения
с реальным Maven; для их проверки и предусмотрено сравнение.
